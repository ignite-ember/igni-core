# igni-core 1.0.6

The release the desktop's new sidebar and Files viewer need, and the
backend's half of the Local / Cloud switch. It also carries the fixes
the end-to-end campaign found after 1.0.5 shipped, among them the one
that kept 1.0.5's two wheels from installing together.

## What a reader gets

```bash
pip install 'igni-core[decisions]==1.0.6'
```

- **`igni_core`**: the backend module.
- **`igni`**: the command. `igni -m "…"` runs one task and exits.
- **`igni-cloud`**: the cloud layer, found through the `igni.layers` and
  `igni.storage` entry points. It is 1.0.6 too, and pins
  `igni-core==1.0.6`.

`[decisions]` adds igni's decisions service (Laya, torch), used by
Bypass mode's last check and by `host.decide`.

## What changed

### The sidebar says what every chat is doing

**A chat working in the background shows that it is running.** Every
window is told which chats are running, which wait on the person and
which have an approval pending. Before, the sidebar knew only about
approvals, and only as of the last session list. Now each change is
pushed to every window as it happens.

**A chat whose run finished while the person was elsewhere is unread
until they open it.** Opening a chat marks it seen, in every window.
What the person has seen is kept in the global database, so it follows
them across windows, devices and VMs and survives a restart. A run that
finishes later makes the chat unread again.

**Chats are listed newest first by their last message.** A message sent
into a chat moves it to the top before the reply starts. Before, a chat
moved only when a reply finished, or when it was renamed. A chat with no
message recorded yet is placed by when it was last updated.

### A changed MCP config takes effect without a restart

**Reloading the MCP config picks up a `.mcp.json` edited before the
first connect.** Every `ensure_mcp` call now re-reads the `.mcp.json`
files, the first call included. Before, the first connect used what the
file said when the session was built. A server added or edited in
between then started its old command. A later call reconnects only the
servers whose config changed and drops the removed ones. The desktop's
"Reload MCP config" control calls it. If the file cannot be read, the
backend keeps the config it last read.

### Files open as images and PDFs, and search reaches every chat

**An image or a PDF can be previewed inline.** `read_file_bytes` is the
binary sibling of `read_file`. It uses the same sandbox (the session's
project folder and `~/.igni`), allows up to 10 MiB, and returns the
bytes as base64 with a media type. The two methods share one path
resolver, so their sandboxes cannot drift apart.

**Search finds text in every chat of the project, not just the open
one.** Each hit names the chat it was found in. Hits from the newest
chat come first.

**A plugin's category reaches the client**, so the marketplace can be
filtered and sorted by it.

### The backend's half of the Local / Cloud switch

**An organisation can run igni for its people in the cloud.** A group's
signed policy now carries a `mode`. If it is `cloud`, igni does not run
on the person's computer; it says "Your organisation runs igni for you
in the cloud.", and the person's VM keeps running igni. A missing or
unknown mode means `local_and_cloud`, which is how things worked before.
A `cloud` group needs the first igni-app release after 1.0.5. An older
desktop ignores `mode` and keeps running igni locally.

**`--account-only` runs a backend that only does sign-in and the
group's policy.** It serves `login` and the account RPCs the app
forwards, and syncs the policy pack. It starts no agent, tools, MCP,
extensions, scheduler or event pull. A test checks that its startup
memory stays within the full backend's plus 10%, and under 320 MiB.

**Extensions work in cloud mode.** Their pages reach the VM through the
gateway's page route. Only a connection the gateway marks may speak for
an extension; one without the mark is refused.

**A desktop whose events are pulled by the cloud waits and asks
again.** A `409 events_owned_elsewhere` answer makes the desktop idle
and retry every 60 seconds. It is not counted as a failure.

**A cloud VM opens no native file dialog.** `pick_dir_native` answers
`unavailable` there.

**A service token cached before a cloud VM slept is not served after
it.** The token cache now measures expiry on the wall clock. The old
clock stopped while the VM was suspended, so a page got a token that had
already expired.

### Approvals and cancelling a paused run

**Cancelling a run that waits on an approval ends it.** Before,
`cancel_run` answered `cancelled: false`, the approval stayed live, and
answering it later still ran the tool. Now the run's pending approvals
are dropped. The cancel also ends the stream with the same `info` and
`stream_end` a cancelled running turn sends.

**Only someone who may answer the approval may cancel the run or write
into its session.** While a session waits on a person, a program
without an approver token is refused. An extension needs
`chat.approvals` to cancel the run or to post into the session on
screen.

**A new message drops the approvals of a paused run**, both live and
after a backend restart. Before, answering the stale approval ran the
abandoned run's command.

**Every lane of a workflow can ask for approval.** The lanes share one
relay, and the first lane to finish used to close it. A lane still
running then had nowhere to ask, and its call stopped. The relay now
stays open until the last lane is done.

**The pause error says what happened in plain words.** It no longer
repeats an internal label after `Error:`, and it names the tools in
prose, not as a Python list.

### Models and tools

**The `gemini` provider works.** Google refused every request igni sent,
because one tool's schema had an array with no `items`. At the Gemini
boundary, igni now gives every array an `items` field. What other
providers receive is unchanged. `docs/CONFIGURATION.md`'s example now
names `gemini-3.8-flash`, because Google no longer gives new keys
`gemini-2.5-flash`.

**An unknown `--model` is refused before a session starts.** The name is
said once, with the fix, on stderr, and the exit code is 1. No failed
run is saved for `igni -c` to resume. The cloud catalogue is refreshed
first, so a model the person's server offers is still found.

**The LSP tool sends notifications as notifications.**
`textDocument/didOpen` and the spec's other notifications go out
without an id, so the document is opened and diagnostics come back.
Before, the server refused them with `-32601`. The tool's schema, as the
model reads it, is unchanged.

**The visualizer's recap says what the card actually drew.** The client
reports what it drew and what it could not draw, through the new
`report_visualization_verdict` RPC. The recap that reaches the parent
agent quotes that report. Without a client, or without a report within
1.5 seconds, the recap stays as before.

**A headless run hears the conditions an extension reports.** `igni -m`
and `--pipe` used to drop them, so an extension's `when:` prompt
overrides never applied there. With CodeIndex installed, a headless
run's prompt now carries the CodeIndex section.

### Installs and the command line

**igni-core and igni-cloud install together again.** 1.0.5 shipped
igni-cloud at 1.0.4, pinned to `igni-core==1.0.4`, so installing both
wheels failed as unsatisfiable. That stopped the Fleet node's host venv
and the guest image. Both are 1.0.6 now, and a test keeps the versions
the same.

**ripgrep installs from a wheel on Ubuntu 22.04.** Linux x86_64 pins
`ripgrep==14.1.0`, the last release with wheels for its glibc, so a
first launch needs no Rust toolchain. An `rg` on PATH still wins.

**`igni ext init` runs on a Windows console.** The scaffold writes its
files as UTF-8, and output with characters a cp1252 console cannot
print no longer crashes the command.

**Headless output is not wrapped at 80 columns.** When the output is
not a terminal, the text is printed as it is, so a path can be copied
in one piece. A terminal gets the same rendering as before.

**An air-gapped machine with an incomplete decision-model copy is told
how to fix it.** It gets the same remedy as a machine with no copy at
all.

### The rest

- An extension process whose service token was refused gets a new one:
  the loopback token endpoint honours `X-Igni-Token-Refresh: 1`. The
  token is still for the same service only.
- `/plugins disable` refuses a managed plugin, using the same words as
  the panel. Before, it answered "disabled" and the plugin stayed on.
- A window open in two tabs stays one window until its last tab closes.
- The PyPI page says what igni is.

## For integrators

- **New RPC methods:** `read_file_bytes`, `search_all_chats`,
  `list_session_states`, `mark_session_seen` and
  `report_visualization_verdict`.
- **New push channel:** `session_states_changed`. It lists each chat
  that is running, waiting or unread, with `waiting_approvals` and
  `last_message_at`, and a `cause`: `activity`, or `seen` after
  `mark_session_seen`.
- **`list_sessions`** returns rows newest first by last message. Each
  row adds `unread` and `last_message_at`.
- **`ensure_mcp`** re-reads the `.mcp.json` files on every call. Its
  description used to say a later call does nothing.
- **`cancel_run`** ends a run that waits on an approval. Without an
  approver token, it is refused while the session waits.
- **New host-model members:** `host.sessions.states`,
  `host.sessions.mark_seen()`, the `sessions.states_changed` signal,
  `host.chat.search_all()` and `host.workspace.read_bytes()` (which
  returns `FileBytes`).
- **New database migration:** `c8e4f2a6b9d1` adds `ember_session_reads`
  (`finished_at`, `seen_at` and `last_message_at`, in Unix
  milliseconds) to the global database. A local backend applies it the
  first time it opens the database. In the cloud, `igni migrate`
  applies it.

## Upgrading

- `pip install --upgrade 'igni-core[decisions]==1.0.6'` installs the new
  backend in the same environment.
- The desktop app installs this release itself, at the version it is
  built for (`igni-core` and the app share one version number).

## Verifying it

`SHA256SUMS` lists every file on the release. Each has GitHub build
provenance, a CycloneDX SBOM, and, when the signing key is present, a
cosign signature over the checksums. See
[docs/VERIFYING_RELEASES.md](https://github.com/ignite-ember/igni-core/blob/main/docs/VERIFYING_RELEASES.md).
