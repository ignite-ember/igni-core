# igni-core 1.0.7

A small release. igni now notices when a message is pleased or
displeased with it, and tells every window and every extension, so a
client can react to it. Nothing else changed.

## What a reader gets

```bash
pip install 'igni-core[decisions]==1.0.7'
```

- **`igni_core`**: the backend module.
- **`igni`**: the command. `igni -m "…"` runs one task and exits.
- **`igni-cloud`**: the cloud layer, found through the `igni.layers` and
  `igni.storage` entry points. It is 1.0.7 too, and pins
  `igni-core==1.0.7`.

`[decisions]` adds igni's decisions service (Laya, torch), used by
Bypass mode's last check, by `host.decide`, and now by the sentiment
reading below.

## What changed

### igni hears how a message feels about it

**Every window is told when a message is pleased or displeased with
igni.** When a person sends a chat message, the backend asks the local
Laya decisions model how the message feels about igni. Thanks and praise
count as positive. An insult, frustration, or saying igni is wrong or
did not do what was asked counts as negative. Only a positive or a
negative reading is sent; a neutral message sends nothing. Laya has to
be at least 60% sure.

**The run never waits for it.** The question is asked in the background,
beside the run. If Laya is not installed, cannot answer, or takes longer
than a minute, nothing is sent and the person sees no difference.

**Only messages Laya can read whole are asked about.** A message that is
empty, or longer than 1,200 characters, is not asked about. That limit
stays under what Laya reads without cutting in every language measured.

**The reading says which turns it is about.** It names the run the
message started and the run of igni's last reply before it, so a later
listener can find both turns. At the start of a session there is no
earlier reply.

**The reading says why, as well as what.** In the same call, Laya is
asked six more questions about the message:

- what displeased the person, if anything (for example a wrong answer,
  a misunderstood request, unfinished work, an ignored instruction, or
  something deleted or run that was not wanted);
- what pleased them, if anything (solved, fast, clearly explained, or
  beyond what was asked);
- whether the same problem happened again;
- whether they ask igni to redo or undo something;
- whether they say the task is done or works;
- how strong the feeling is, from none to angry.

Each answer comes with the label Laya chose and the probability of every
label, so whoever listens can apply its own thresholds later. Some are
weaker signals than the verdict itself: "happened again" and the
strength of feeling, and the two "what" questions on messages that are
not in English.

**No model-facing text changed.** The model igni chats with sees the same
prompts and tools as in 1.0.6.

## For integrators

- **New push channel:** `user_sentiment`. Its payload
  (`UserSentimentPayload`) has `session_id`, `sentiment` (`positive` or
  `negative`), `confidence` (0 to 1), `message_run_id`, `reply_run_id`
  (either may be `null`) and `aspects`.
- **`aspects`** (`SentimentAspects`) has one `SentimentAspect` per
  question: `feeling`, `gesture`, `negative_reason`, `positive_reason`,
  `repeat`, `redo_requested`, `task_done` and `intensity`. Each holds the
  chosen `answer` and `probabilities`, a list of `LabelProbability`
  (`label`, `probability`) in the question's order.
- **New host-model signal:** `chat.sentiment`, carrying the same fields
  as the push, with the new `Sentiment`, `SentimentAspects`,
  `SentimentAspect` and `LabelProbability` types.
- `docs/rpc-contract.json` and `docs/host-schema.json` describe the new
  channel, signal and types.

## Upgrading

- `pip install --upgrade 'igni-core[decisions]==1.0.7'` installs the new
  backend in the same environment.
- The desktop app installs this release itself, at the version it is
  built for (`igni-core` and the app share one version number).
- Without the `[decisions]` extra, igni works as before and sends no
  sentiment readings.
